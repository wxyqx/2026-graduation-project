# 后端代码导读（从零开始读懂这个系统）

> 给第一次读代码的你。不需要会编程，跟着顺序读就行。每个 `.py` 文件开头都有一段中文说明，
> 告诉你「这个文件是干什么的」；函数里也有注释解释每一步在做什么。

## 一、先搞清楚三个词

| 词 | 大白话 |
| :--- | :--- |
| **前端** | 你在浏览器里看到、点到的网页（Vue 3，`ats/frontend`；HR / 候选人 / 技术端三套入口） |
| **后端** | 藏在后面干活的程序：存数据、算数、请 AI 帮忙。就是这个 `backend/` 文件夹 |
| **接口** | 前端和后端说话的「窗口」。前端说「给我岗位列表」，后端从窗口把数据递出去。每个接口就是一个网址 |

浏览器打开 http://127.0.0.1:8000/docs 能看到所有接口，每个都有中文说明。

## 二、一次请求是怎么走完的？

以「前端要看岗位列表」为例：

```
浏览器 ──GET /api/positions──▶ main.py（总开关，把请求转给对应路由）
                                   │
                                   ▼
                          core/deps.py（门卫：检查登录 token，不合格回 401）
                                   │
                                   ▼
                     routers/positions.py（前台：list_positions 函数）
                                   │
                                   ▼
                      models/position.py（货架：Position 表长什么样）
                                   │ 通过 core/database.py 借的「小推车」去数据库拿数据
                                   ▼
                    schemas/position.py（表格模板：整理成 PositionOut 的样子）
                                   │
                                   ▼
浏览器 ◀───────── JSON 数据 ────────┘
```

记住这条链：**main → deps（门卫）→ routers（前台）→ services（后厨）/ models（货架）→ schemas（回单）**。

## 三、推荐阅读顺序

按下面顺序读，每个文件 5～10 分钟：

### 第 1 站：数据长什么样 —— `app/models/`
1. `models/__init__.py` — 12 张表的总览
2. `models/application.py` — **最重要**，投递记录的 7 关是怎么存的
3. `models/user.py` — 三角色账号（hr / candidate / admin）
4. `models/candidate_file.py`、`form_template.py`、`form_submission.py` — v3.15 新增的文件与表单

### 第 2 站：闯关规则 —— `app/services/state_machine.py`
整个系统的核心逻辑。读懂 `apply_result`（打分后怎么走）和 `revert`（怎么撤回）就懂了一半。
文件里有举例。

### 第 3 站：门怎么开 —— 登录
1. `services/security.py` — 密码怎么「搅碎」存、token 怎么「盖章」发
2. `core/deps.py` — 门卫怎么验 token；`get_current_hr` / `get_current_candidate` / `get_current_admin` 三个角色门卫
3. `routers/auth.py` — HR 注册、登录接口
4. `routers/portal_auth.py`、`routers/tech_auth.py` — 候选人 / 技术端登录

### 第 4 站：前台接待 —— `app/routers/`
先读 `routers/__init__.py` 的说明，再读 `positions.py`（最简单的增删改查），
然后 `applications.py`（调用状态机）。候选人走 `portal_*.py`，技术端走 `tech_*.py`，其余照葫芦画瓢。

### 第 5 站：候选人材料与表单
1. `services/file_service.py` — 文件校验、BLOB 入库、简历版本
2. `services/form_service.py` — 模板字段、答卷校验、版本与软删除
3. `services/portal_apply.py` — 候选人投递的 AI 首筛与降级

### 第 5 站：请 AI 帮忙 —— AI 录入
1. `services/pdf.py` — 从 PDF 里抠文字
2. `services/llm.py` — 怎么跟 AI 说话、怎么读它的回答
3. `services/ai_screen.py` — **三步流水线**总指挥（文件头有整体说明）
4. `routers/ai_screen.py` — 上传文件的接口

### 第 6 站：数数和导出
- `routers/stats.py` — 各种计数
- `services/export.py` + `routers/export.py` — 生成 Excel

### 第 7 站：怎么确认没写错 —— `scripts/`
- `smoke_test.py` — HR 全接口与状态机（186 项）

## 四、读代码时的小提示

- **看到 `Depends(...)`**：意思是「这个参数不用前端传，FastAPI 自动帮我准备好」。`Depends(get_db)` 准备数据库小推车，`Depends(get_current_user)` 准备当前登录用户。
- **看到 `db.add / db.commit / db.refresh`**：三连招 = 放进推车 → 结账写入 → 重新读一遍拿到编号。
- **看到 `raise HTTPException(status_code=xxx)`**：直接给浏览器回一个错误码。常见的：400 你传的参数不对、401 没登录、404 没这东西、409 冲突（重复了）、422 格式不对。
- **看到 `async` / `await`**：「异步」，等慢动作（等 AI 回话、等文件读完）时不傻等，可以同时干别的。只在 AI 录入那条链上出现。
- **看到 `select(...).where(...)`**：拼一条查询，像搭积木：查什么表、什么条件、怎么排序。

## 五、怎么自己动手试

```bash
cd backend
.venv\Scripts\uvicorn app.main:app --host 127.0.0.1 --port 8000     # 起服务
.venv\Scripts\python scripts\smoke_test.py http://127.0.0.1:8000     # 另开一个窗口跑体检
```

改了任何代码，重启服务、再跑一遍体检，全绿就说明没改坏。
