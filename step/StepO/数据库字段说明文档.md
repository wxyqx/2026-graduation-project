# 数据库字段说明文档（数据字典）

> 数据库：MySQL 8.0（utf8mb4）
> 建表脚本：[crebas.sql](crebas.sql)（v3.15，12 张表）
> 迁移脚本：[migrate_v3.15_three_portal.sql](migrate_v3.15_three_portal.sql)；回滚：[rollback_v3.15_three_portal.sql](rollback_v3.15_three_portal.sql)
> 枚举取值：阶段 / 结果 / 状态 / 角色 / 来源 / 文件分类 / 表单类型见文末枚举字典

> **v3.15 变更摘要**：新增三角色 `User.role`；候选人手机号即账号 `Candidate.phone`；投递来源 `Application.source`；
> 新增 6 张表（文件、表单模板/字段/答卷/答案、操作日志）。全部只加不删，存量数据不受影响。

## Candidate 表（候选人）

表注释：存储投递简历的候选人基础信息

| 字段名 | 数据类型 | 约束 | 中文名称 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| ID | INT | 主键，NOT NULL，自增 | 候选人编号 | 候选人唯一标识，插入时无需传值 |
| create_time | DATETIME | - | 创建时间 | 候选人记录创建时间 |
| name | VARCHAR(255) | - | 姓名 | 候选人姓名 |
| phone | VARCHAR(20) | 唯一，可空 | 手机号 | **候选人端登录账号**；有值即自动开通账号；格式 `^1[3-9]\d{9}$` |
| email | VARCHAR(100) | 可空 | 邮箱 | 可空，仅展示，不做验证 |
| remark | VARCHAR(500) | - | 备注 | 备注（来源渠道、特殊情况等） |
| owner_id | INT | 可空，外键→User.ID | 负责人 HR | 默认 = 建档 / 上传简历录入的 HR（v3.16）；能编辑该候选人全部关卡；技术管理端可单个/批量改；NULL=暂无，任意 HR 可编辑 |
| Onboard_Date | VARCHAR(50) | 可空 | 到岗时间 | HR 从简历摘录，可写「随时」等 |
| School | VARCHAR(100) | 可空 | 毕业院校 | HR 从简历摘录 |
| Degree | VARCHAR(20) | 可空 | 学历 | 大专/本科/硕士/博士/其他 |
| Major | VARCHAR(100) | 可空 | 专业 | HR 从简历摘录 |
| Expected_Salary | VARCHAR(50) | 可空 | 期望薪资 | HR 从简历摘录 |
| Work_Location | VARCHAR(100) | 可空 | 期望工作地点 | HR 从简历摘录 |
| Hire_Type | VARCHAR(20) | 可空 | 招聘类型 | 校招/社招 |
| Work_Experience | TEXT | 可空 | 工作经历 | HR 从简历摘录；与表单答卷独立 |

### Candidate_Notice（候选人通知：通过关卡时按模板发送）

| 字段 | 类型 | 约束 | 说明 | 备注 |
| :--- | :--- | :--- | :--- | :--- |
| ID | INT | PK，自增 | 通知编号 | |
| Candidate_ID | INT | 外键→Candidate.ID，CASCADE | 所属候选人 | |
| Application_ID | INT | 外键→Application.ID，SET NULL | 关联投递 | 可空 |
| Stage | VARCHAR(20) | NOT NULL | 触发关卡 | phone / test / pro / hr / final / onboard（onboard=入职通知） |
| Title | VARCHAR(100) | NOT NULL | 通知标题 | 按模板渲染 |
| Body | TEXT | 可空 | 通知正文 | 按模板渲染 |
| Send_Time | DATETIME | NOT NULL | 发送时间 | |
| Read_Time | DATETIME | 可空 | 候选人阅读时间 | NULL=未读（登录弹窗只看未读） |
| update_time | DATETIME | - | 更新时间 | 最近一次修改时间 |

> 手机号允许为空：AI 录入 / HR 手工建档时可能还没拿到手机号；没有手机号就不能登录候选人端，通知也就发不出去——点「发送」会提示失败（后端 send_notice 校验），补上手机号后才能重试。

## User 表（账号：HR / 技术管理员 / 候选人）

表注释：三个端共用一张账号表，靠 role 区分；密码只存 bcrypt 哈希

| 字段名 | 数据类型 | 约束 | 中文名称 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| ID | INT | 主键，NOT NULL，自增 | 用户编号 | |
| username | VARCHAR(50) | 唯一，可空 | 用户名 | HR / 技术管理员用；候选人账号为 NULL |
| phone | VARCHAR(20) | 唯一，可空 | 手机号 | HR / 技术管理员的联系方式（个人信息必填，v3.16）；候选人账号为 NULL，手机号在 Candidate 表 |
| real_name | VARCHAR(50) | 可空 | 实名 | HR / 技术管理员的姓名（个人信息必填，v3.16）；候选人账号为 NULL，姓名在 Candidate 表 |
| password_hash | VARCHAR(100) | NOT NULL | 密码哈希 | bcrypt，不存明文 |
| role | VARCHAR(20) | NOT NULL，DEFAULT 'hr' | 角色 | candidate / hr / admin（v3.15） |
| candidate_id | INT | 唯一，可空，外键→Candidate.ID | 候选人编号 | 候选人账号专属；HR/管理员为 NULL；删除候选人时置 NULL（v3.15） |
| is_active | TINYINT | NOT NULL，DEFAULT 1 | 启用 | 0=停用，禁止登录（v3.15） |
| must_change_password | TINYINT | NOT NULL，DEFAULT 0 | 默认密码提示 | 1=还在用默认密码，登录强提示改密；改密/重置后置 1、改密成功清零（v3.16） |
| restore_time | DATETIME | - | 恢复时间 | 淘汰销号账号的恢复时间（v3.16）；技术管理员在保存期（销号后 3 个月）内启用即恢复，晚于某次淘汰的恢复记录使那次淘汰不再拦截登录 |
| last_login_time | DATETIME | - | 最近登录时间 | （v3.15） |
| last_login_ip | VARCHAR(45) | - | 最近登录 IP | 兼容 IPv6（v3.15） |
| Avatar | LONGBLOB | 可空 | 头像图片内容 | 仅 image/*，≤5MB；NULL=未设置（前端首字占位） |
| Avatar_Mime | VARCHAR(50) | 可空 | 头像 MIME 类型 | 三个端共用，按登录账号上传 |
| create_time | DATETIME | - | 创建时间 | |

## Candidate_File 表（候选人文件，v3.15 新增）

## 部署检查项（v3.15）

1. `max_allowed_packet >= 16M`（默认 64M，可用 `SHOW VARIABLES LIKE 'max_allowed_packet';` 确认）。
2. 磁盘预留：BLOB 入库会放大数据库体积，建议至少留 1GB 余量。
3. 迁移前 `mysqldump` 备份；先跑 `migrate_v3.15_three_portal.sql`，再启动后端。
4. 老库升级后，存量 `User` 全部为 `hr`；技术管理员用 `scripts/create_user.py --role admin` 创建。
5. 候选人必须先在系统里有手机号才能登录；存量候选人可在 HR 端逐个补录。
