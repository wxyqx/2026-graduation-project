> v3.13 变更：**移除「联系候选人（contact）」环节**——招聘流程由 8 关精简为 7 关（ai → resume → phone → test → pro → hr → final）。该环节原本在表里就没有结果/时间字段、只是个纯流程节点，删除后状态机、统计漏斗、交叉表、阶段轨、详情时间线、导出与数据字典同步为 7 关，阶段色阶 `--ats-stage-1..7` 相应收窄。存量数据无影响（库中无投递停在 contact 关）。

> v3.10 变更：**投递详情页支持修改候选人姓名**——AI 识别简历有时会认错名字（典型情况是把 PDF 文件名当成了姓名），现有 2 条历史数据即为此类；候选人编辑接口开放 `name` 字段（不允许改空），改成与已有候选人重名时先返回 409 并提示对方投递数，带 `confirm_duplicate` 确认后允许；改名不影响任何投递记录（按候选人编号关联）

## 一、技术栈

| 层 | 选型 | 说明 |
| :--- | :--- | :--- |
| 开发环境 | **Windows 原生**（不装 WSL/Linux） | Python、MySQL、Node 全部装 Windows 版；终端用 PowerShell |
| 后端 | Python 3.11+ / FastAPI / SQLAlchemy | Uvicorn 运行，Pydantic 校验参数 |
| 认证 | passlib(bcrypt) 密码哈希 + JWT（python-jose） | 登录后发 token，除 auth 外全部接口校验；AI_API_Config 按 User_ID 隔离数据 |
| 数据库 | MySQL 8 for Windows（utf8mb4） | 建表用 crebas.sql；首次执行跳过开头 drop index 行 |
| 前端 | Vue3 + Element Plus + Vite | 组件全用 Element Plus，JS 只写胶水逻辑，不用 TS |
| AI 筛选 | 用户自配的 LLM API（GLM/Qwen 等，设置页可添加多个并选用） | 只在 ai 阶段调用一次 |
| PDF 解析 | PyMuPDF | 提取简历文本（中文友好）；扫描件提取不到文本时逐条报错提示，不中断批次 |
| 导出 | openpyxl 生成 xlsx（备用 CSV） | 前端下载文件流 |
| 部署 | 本机运行（localhost）；Docker 仅作为日后可选练习 | 不买云服务器 |

- **顶部状态栏（固定）**：全局速览——在招岗位数、进行中投递数、待 AI 筛选数（ai 阶段 pending 计数）、本周进行数，上周完成数；右侧主题三档切换按钮
- **主题三档**：白天（默认）/ 黑夜 / 护眼
  - 黑夜用 Element Plus 官方 dark 模式（html 加 dark class）
  - 护眼自定义一套米黄底 CSS 变量
  - 选择存 localStorage，刷新保持

## 三、页面清单（2 个全屏页 + 5 个后台页）

**全屏页（不在后台布局内，未登录时唯一可见）**

0a. **登录页**：居中卡片（el-form）——用户名 + 密码 + 登录按钮 + 「去注册」链接；失败提示用户名或密码错误
0b. **注册页**：用户名 + 密码 + 确认密码；用户名重复返回 409 提示；成功后自动登录跳转首页

**后台页（登录后进入，左侧导航 + 顶部状态栏布局）**

1. **岗位管理**：岗位表格 + 新建/编辑弹窗 + 删除；**行内「招/暂不招」开关**（暂不招=隐藏，该岗位及其投递不再出现在统计与列表中，数据保留可随时恢复）+ **「显示」筛选**（全部/只在招/只暂不招，默认全部）+ 隐藏行整行置灰并带「已隐藏」标签；弹窗内另设「AI 附加条件」文本框——给 AI 的额外筛选限制（如「只要 985/211」「必须有医疗行业项目经验」），**不保存到数据库**，存本机浏览器 localStorage（刷新保留），仅在该岗位被 AI 录入匹配到时作为额外限制注入提示词；表格对有附加条件的岗位显示「AI附加条件」标记
2. **候选人管理**：顶部**搜索栏**（姓名模糊 / 备注模糊 / 投递情况[有投递/暂未投递]，可搜索与重置）+ 候选人列表（姓名/备注/名下投递数/录入时间）；**点击姓名或「详情」打开右侧抽屉**——展示基础信息 + 名下全部投递（岗位/当前阶段/状态/AI结论，可点「查看」跳转投递详情）；行内「删除候选人」——弹窗提示将连带删除其名下 N 条投递、不可恢复，确认后调 DELETE（应用层级联），刷新列表与顶部统计
3. **投递列表**：**顶部为「阶段轨」**——7 关横排、色条按关卡加深、各带本关人数，点一下即筛选该关（再点取消）；下方工具条为状态/岗位筛选（筛选条件同步到网址参数并记忆，刷新/菜单切换后保持）；手动新建投递；行内操作（通过/淘汰/撤回）；**「AI录入简历」按钮+弹窗**——弹窗顶部先**选择应聘岗位**（下拉：`自动识别（由 AI 判断）` 或具体岗位，显示「岗位名 — 负责人」以区分同名岗位），再拖拽/选择上传一个或多个 **PDF 简历**（保留粘贴纯文本兜底）；后端提取文本后由 AI 识别姓名、按所选岗位（或自动匹配）的要求筛选并自动建档；弹窗内逐条反馈结果（姓名/匹配岗位/通过与否/理由/未匹配或文本提取失败原因）；**PDF 与提取文本均不保存**，AI 结论如需修改用行内通过/淘汰/撤回手动覆盖
4. **投递详情**：候选人+岗位信息（**姓名可修改**——点「改姓名」纠正 AI 认错的名字，重名会先提示确认）、8 阶段时间线、各阶段结果与时间戳、操作按钮；AI 筛选理由展示
5. **汇总导出**：
   - 顶部**紧凑指标行**（在招岗位/进行中/已录用/已淘汰/本月录用，数字等宽）
   - **招聘漏斗**：7 关逐关收窄、按阶段色阶着色，一眼看出堵在哪一关；每行同时给出「到达该关的累计人数」与「当前正停在该关的人数」
   - 各阶段人数分布：并入漏斗（原独立卡片取消）
   - **「阶段 × 岗位汇总」交叉表（周报表）**：行=简历筛选数 / 电话沟通人数 / 笔试人数 / 面试人数（面试 = 专业面+HR面+终面，同一人只计一次）；列=各在招岗位 + 总计（首列阶段名固定，末列与末行均为总计）；格子 = **所选时间范围内「通过了这一关」或「正停在这一关」**的人数（在此关被淘汰的不算）：已通过该关（该关 result=pass，含已进入后续环节的）按该关时间戳判范围；正停在该关未打分的按 update_time 判范围——因此不会漏掉「正在这一关等待」的人；「面试人数」只判专业面（过了专业面即计入，含后来过了 HR 面/终面的）；**点数字可弹窗查看该格人员名单**（标注已通过/正等待，可跳投递详情）；岗位名自动缩写为短标签，缩写后重名的岗位自动补负责人（如 `C++客户端(初级)—朱力伟` / `—丘春辉`）；时间范围可切：本周（默认）/ 上周 / 本月 / 全部 / 自定义日期区间；**支持「导出这张表」为 xlsx/csv**（表头与页面一致）
   - **「进行中的候选人所处阶段」清单**：列出所选时间范围内**有动作**（创建或最后更新落在范围内）且仍为**进行中**的投递，按岗位分组显示 岗位 / 候选人 / 阶段；时间范围与上方交叉表共用同一个切换器（联动）；**支持按阶段多选筛选**（如只看待笔试/待专业面）；阶段默认按当前阶段自动生成，**可逐条手动改写**（用于系统没有的说法，如「待offer回传」「待入职 1.11」），改过的行标「手动」并可一键「恢复自动」
   - **导出招聘周报**：一个 Excel 含两个工作表——① 阶段岗位汇总（交叉表）② 进行中候选人（上述清单）；选 csv 时因单文件限制退化为只导第一张表
   - 导出面板：选择数据范围（时间段/岗位/阶段/状态）→ 勾选导出字段 → 导出 xlsx
   - 「按指定格式导出」：预留模板对接位（**格式模板由用户提供后实现**，先交付字段自选导出）
6. **系统设置**：
   - **AI 筛选 API 管理**：列表展示已添加的 API 配置；新建/编辑/删除；每个配置可独立启用/停用（**可同时启用多个**，批量筛选时在启用的配置间轮询分流，避免单个 API 限流）
   - **AI 筛选提示词**：一段可编辑的「筛选规则」（AI 判断简历时的额外标准，如「只要 985/211」「必须有医疗行业项目经验」），按登录用户存于 App_Setting 表；下方以只读灰色框展示**系统锁定的回答格式**（必须输出 JSON、result 只能 pass/fail），该部分不可修改，保证结果一定可解析；带保存与恢复默认
   - 主题偏好展示（主题切换主要在导航栏，设置页放说明）

## 四、API 清单

**认证 Auth**
- `POST /api/auth/register`：参数 `{username, password}`；密码 bcrypt 哈希入库；用户名已存在返回 409
- `POST /api/auth/login`：校验密码 → 返回 JWT token（有效期 7 天）；失败返回 401
- `GET /api/auth/me`：返回当前登录用户信息
- 除 auth 外的所有 `/api` 接口要求 `Authorization: Bearer <token>`；token 无效/过期返回 401，前端统一跳登录页

**岗位 Position**
- `GET /api/positions`（查询参数 `include_hidden`：默认 false=只返回在招岗位，各处下拉即自动过滤；岗位管理页传 true 拿全部）/ `POST /api/positions` / `PUT /api/positions/{id}`（可传 `is_hidden` 切换暂不招）/ `DELETE /api/positions/{id}`（有投递记录时拒绝，外键 restrict）
- 暂不招岗位的投递：不在投递列表中、详情返回 404、不计入任何统计与导出；往暂不招岗位建投递返回 400

**候选人 Candidate**
- `GET /api/candidates`（查询参数：`name` 姓名模糊 / `remark` 备注模糊 / `has_application` yes=有投递、no=暂无投递；可组合；响应含 application_count 名下投递数）/ `POST /api/candidates`（name, remark）
- `PUT /api/candidates/{id}`：可改 `remark`，也可改 `name`（人工纠正 AI 认错的名字）。姓名传空 → 400；新姓名与另一候选人重名 → 409（提示对方投递数），带 `confirm_duplicate=true` 再提交即允许同名；改名不影响该候选人的投递记录
- `DELETE /api/candidates/{id}`：**级联删除**——先删该候选人名下全部投递再删本人（应用层实现，事务内完成）；返回 `{deleted_applications: N}`；候选人不存在 404

**投递 Application**
- `GET /api/applications`，查询参数：stage / status / pos_id / can_id（按候选人查他投了哪些岗位）
- `POST /api/applications`（can_id, pos_id）→ current_stage='ai'，overall_status='pending'；重复投递返回 409
- `GET /api/applications/{id}` 详情
- `POST /api/applications/{id}/advance` 参数 `{fromStage, result}`
  - pass：写该阶段结果+时间戳，current_stage 推进；终面通过 → overall_status='pass'
  - fail：写该阶段结果，overall_status='fail'，流程终止
- `POST /api/applications/{id}/revert` 参数 `{toStage?}`
  - 省略：回退上一阶段，清当前阶段结果+时间戳；指定：回退到 toStage 清其后数据
  - fail/pass 状态撤回自动恢复 pending；第一阶段不可再退
**AI 筛选（单一路径：智能录入）**
- `POST /api/ai-screen/intake`：multipart 参数 `files[]`（PDF，多个）+ 可选 `texts[]`（纯文本兜底）+ 可选 `extras`（JSON 字符串，各岗位的 AI 附加条件 `{"岗位id":"限制文字"}`，前端从浏览器本地带入）+ 可选 `pos_id`（应聘岗位编号）——**AI 录入唯一入口**。每个 PDF 先经 PyMuPDF 提取文本（提取过短判为扫描件，该条返回"无法提取文本"不中断批次）。
  - **指定岗位模式（传了 pos_id）**：只把该岗位给 AI，提示词明确「岗位已指定，只需判断是否符合」，AI 返回的岗位一律忽略，强制挂到所选岗位；
  - **自动模式（不传 pos_id）**：把全部岗位给 AI 由它挑，提示词要求「技术方向明显对应才选，否则一律 null」（宁可不匹配也不硬凑）。
  每份简历由 LLM 识别姓名、给出 pass/fail + 理由（岗位含 extra 时须同时满足，违反即 fail）。姓名匹配已有候选人则复用、否则新建（仅存姓名）；创建投递（current_stage='ai'）并写 ai_result、ai_comment，按结果自动执行 advance；已投递同岗位则返回重复提示不再建档；未匹配岗位则不建档。**回答解析容错**：result 支持 pass/fail 及「通过/合格/是/true/1、淘汰/否/false/0」等写法归一化，兼容中文键名与 position_id 的 "1"/"1.0"/"岗位1" 等写法，JSON 用括号配对提取；答非所问（认不出结论）会换已启用配置重试一次并追加严格格式要求。asyncio 并发，任务在已启用配置间轮询分配；逐条返回结果。**原 PDF 与提取文本均不落盘**，仅结果写入 ai_result / ai_comment；无已启用配置时整体返回 400；pos_id 不存在返回 400

**AI 配置 AiApiConfig**
- `GET /api/ai-configs` / `POST /api/ai-configs` / `PUT /api/ai-configs/{id}` / `DELETE /api/ai-configs/{id}`
- `PUT /api/ai-configs/{id}/enable` / `PUT /api/ai-configs/{id}/disable` 启用/停用（可同时启用多个）

**系统设置 Setting**
- `GET /api/settings/ai-prompt`：读取 AI 筛选提示词（返回当前规则 rules、是否自定义 is_custom、系统默认规则 default_rules、锁定的格式说明 format_rules）
- `PUT /api/settings/ai-prompt`：保存提示词，参数 `{rules}`；传空 = 恢复系统默认。按登录用户隔离

**汇总与导出**
- `GET /api/stats/overview`：统计卡数据（各阶段/状态计数，按岗位分组）
- `GET /api/stats/matrix`：**阶段 × 岗位 交叉汇总表**。参数 `range`（week 本周默认 / last_week 上周 / month 本月 / all 全部 / custom 自定义，自定义需配 `start_date`、`end_date`）；返回 `{range, range_label, start, end, positions[{id,name,label,owner}], rows[{key,label,cells[],total}], col_totals[], row_totals[], grand_total}`；起止日期颠倒返回 400
- `GET /api/stats/matrix/cell`：**交叉表某个格子的具体人员名单**。参数 `row`（resume/phone/test/interview）+ `pos_id` + `range`（同 /stats/matrix）；返回 `{row, row_label, position_id, position_label, count, people[{app_id, candidate_id, name, stage_text, is_custom, passed, overall_status, current_stage}]}`，`state` 三态：`passed`=已通过该环节 / `waiting`=正等待 / `rejected`=该环节被淘汰（面试行会出现）；row 非法或岗位不存在返回 400
- `GET /api/stats/in-progress`：**进行中的候选人所处阶段清单**。参数同 `/stats/matrix`，另有 `stages`（可重复传，如 `stages=test&stages=pro`，只返回当前处于这些阶段的人；非法值 400）；只收 `overall_status='pending'` 且在范围内有动作（create_time 或 update_time 命中）的投递；返回 `{range, range_label, start, end, groups[{position_id, position_label, position_name, owner, candidates[{app_id, candidate_id, name, stage_key, stage_text, auto_text, is_custom, update_time}]}], total}`
- `PUT /api/settings/stage-note`：手动改写某条投递的阶段文案，参数 `{app_id, note}`；note 传空 = 恢复自动生成；存 App_Setting（键 `stage_notes`，值为 JSON），按登录用户隔离
- `POST /api/export`：参数 `{filters, fields[], format, mode, range}`，返回 xlsx 文件流。`mode='records'`（默认）逐条导出投递记录；`mode='matrix'` 导出交叉汇总表（忽略 fields，文件名 `阶段岗位汇总_{范围}_{时间戳}.xlsx`）；`mode='report'` 导出**招聘周报**（两个工作表：阶段岗位汇总 + 进行中候选人，文件名 `招聘周报_{范围}_{时间戳}.xlsx`；format=csv 时退化为只导第一张表）

**校验规则**：fromStage 必须等于当前 current_stage（防重复操作）；枚举值以数据字典为准；AI_API_Config 与 App_Setting 的增删改查均只针对当前登录用户的 User_ID；intake 的 pos_id 不存在返回 400。

## 八、约定

- 枚举值照抄数据字典，不自造值
- Git 管理（Windows 本地仓库；日后想补 Linux 功底再迁移 WSL，方案无缝）
- 本项目是工程化练习，控制投入；主线在 PyTorch 分布式学习路线（届时 Linux 环境通过 WSL2 或 GPU 云解决，与本项目解耦）
- AI 提示词：筛选规则可自定义（存 App_Setting），回答格式系统锁定不可改（保证结果可解析）
- AI 录入岗位：默认「自动识别」，也可在弹窗整批指定具体岗位（指定后 AI 只判断是否符合该岗位）
- 周报口径：交叉表格子=范围内「到达该关」人数；进行中清单=范围内「有动作」且仍进行中的人；阶段文案可手动改写（存 App_Setting，不改业务数据）
- 「暂不招」岗位：`Position.is_hidden=1`，该岗位及其全部投递在统计、下拉、列表、AI 筛选、导出中彻底不体现（数据保留，改回即恢复）
- 删除候选人会连带删除其名下全部投递记录（应用层级联，自用系统不做回收站）；岗位有投递时仍拒绝删除（外键 restrict）
